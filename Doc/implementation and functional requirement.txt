Part 1 — System Overview & Stakeholder Goals
1.1  What We Are Building
The Distributed Task Scheduler is a backend-centric, real-world distributed computing platform modeled after industry systems such as Google MapReduce, Apache Spark Job Scheduling, and Kubernetes CronJobs. Users submit large logical jobs that the system automatically decomposes into fine-grained parallel tasks. Those tasks are dispatched to a pool of independent worker nodes that execute concurrently, report results, and recover from failures without human intervention.

  Core Value PropositionThe system turns a single large job (e.g., process 1,000 records) into N parallel tasks executed by M workers.
Throughput scales linearly with the number of workers. The system self-heals when workers crash.
Every architectural decision is grounded in real distributed systems principles: atomicity, fault tolerance, and decentralized execution.

1.3  System Boundaries
The system boundary includes: the Laravel coordinator API, the MySQL database, the Redis queue/cache layer, worker processes (Laravel artisan commands), the Vue 3 dashboard SPA, and the Docker Compose network. The system boundary excludes: the actual business logic of task payloads (simulated with sleep/arithmetic), authentication/authorization infrastructure (out of scope for class project), and external third-party integrations.

3.1  Worker Management Requirements

FR-WRK-01  Worker Self-Registration   [MUST]ActorWorker Process (Artisan Command)DescriptionA worker process MUST register itself with the coordinator upon startup before attempting to claim any tasks. Registration is idempotent — re-registering an existing worker_key reactivates it.Pre-conditionsNo prior registration required (first boot scenario)
System is running and /api/workers/register endpoint is reachableMain Flow1. Worker sends POST /api/workers/register with {worker_key, hostname, ip_address}
2. Coordinator validates: worker_key not empty, hostname not empty
3. Coordinator calls Worker::firstOrCreate(['worker_key'=>...], [hostname, ip, status=idle, last_heartbeat_at=now()])
4. If worker_key already exists (restart): updates last_heartbeat_at, resets status to idle, clears current_task_id
5. Returns HTTP 201 (new) or 200 (existing) with full worker JSONAlt/Error Flowworker_key missing or empty: HTTP 422 with field-level error
Coordinator DB unreachable: worker retries registration every 5 seconds up to 10 attempts then exits with errorPost-conditionsWorker record exists in DB with status=idle
Worker has its own worker_id for subsequent calls
Worker appears in dashboard workers panel

FR-TASK-01  Atomic Task Claiming (No Race Conditions)   [MUST]ActorWorker ProcessDescriptionWhen a worker requests the next available task, the system MUST guarantee that only ONE worker receives each task, even under heavy concurrent load. This is the most critical correctness requirement in the system.Pre-conditionsWorker is registered
At least one task exists with status=pending and available_after <= NOW()Main Flow1. GET /api/tasks/next (Header: X-Worker-Key: worker-001)
2. Coordinator calls TaskClaimService::claimNext(workerKey)
3. Begin MySQL transaction (InnoDB)
4. SELECT id FROM tasks WHERE status='pending' AND (available_after IS NULL OR available_after<=NOW()) ORDER BY created_at LIMIT 1 FOR UPDATE
5. If result is NULL: COMMIT, return HTTP 204
6. Else: UPDATE tasks SET status='assigned', worker_id=$worker_id, assigned_at=NOW() WHERE id=$task_id
7. UPDATE workers SET status='busy', current_task_id=$task_id WHERE id=$worker_id
8. COMMIT
9. Return HTTP 200 { task: {id, job_id, payload, timeout_seconds, ...} }Alt/Error FlowNo tasks available: HTTP 204 No Content (worker sleeps 3s and retries)
Worker key not found: HTTP 401
Deadlock (rare): MySQL auto-detects, rolls back one transaction, returns error. Service retries once.Post-conditionsWorker receives exactly one unique task
No other worker can receive the same task
Task status = assigned, worker_id = requesting worker

2.1  Worker Artisan Command
// app/Console/Commands/WorkerRun.php
class WorkerRun extends Command {
    protected $signature = 'worker:run {--key=worker-001} {--sleep=3}';
    protected $description = 'Run a distributed task scheduler worker node';

    public function handle(): void {
        $this->workerKey = $this->option('key');
        $this->info("[{$this->workerKey}] Starting worker...");
        $this->register();
        $this->startHeartbeatTimer();
        $this->pollLoop();
    }
}
